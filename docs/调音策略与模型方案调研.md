# 调音策略与模型方案调研（v10.1）

本文记录 BriVoice 10.1 的方案选择、实现与自测数据。先说明可信度边界。

## 0. 前提与限制

- 本机联网检索不可用，本次调研**没有**拿到任何在线资料：`web_search` 返回 `configured web provider "ddg" is not registered`，`web_fetch` 返回 `"fs-quality-fetch" is not registered`，直接 DNS 解析也失败（`Could not resolve host`）。因此下面没有引用外部链接，凡是涉及其他模型结构的尺寸、精度均为**本地领域知识的近似值**，不是抄来的论文数字；需要精确参数时应在联网环境复核。
- 真正可靠的是本机可复现的数据：真实工程（HUG.vsqx）的曲线统计、自己生成的 16.7 万条教师样本、桌面合成信号测试、LDPlayer 真机测得的音高偏移。
- 硬约束：模型参数 ≤ 0.8B；中端 Android 机可离线运行；APK 不内嵌权重（沿用 `aimodel/` 在线下载 + SHA-256 校验）；结果可撤销、可导出 JSON。

## 1. 要做的事

输入两种：

1. 结构化工程：当前音轨的音符（音高、时长、歌词、位置）、前后间隔、速度、风格标签；输出 11 个值：DYN/BRE/BRI/CLE/OPE/POR/VIB/PIT 前段/PIT 后段/力度/GEN 的偏移。
2. 干声 WAV（v10.1 新增，可选）：逐帧音高 + 响度，转成 PIT/DYN/VIB 曲线。

输出必须落到现有的 `Tuning` JSON，复用 `applyTuning` 的撤销栈，因此模型只是「曲线的生成器」。

## 2. 调音策略调研（本地知识 + 工程实测）

### 2.1 规则 / 启发式

常见的中文虚拟歌手调音规则：

- 长音渐弱、句尾释放；句首轻微气声；高音减力、低音加力；大跳按音程与时值做滑音（portamento），相邻同音或极短间隔不做滑音；长音延迟起颤（vibrato 渐入）、短音去颤；强拍 / 弱拍 / 反拍的力度层次；五声音阶与风格化处理（流行偏直、抒情偏气声、摇滚偏硬起音、电子偏短促、国风偏滑音）。
- 优点：可解释、可单测、零训练成本；缺点：规则一多就互相打架，需要人工调参。

本次把这些规则当作**教师**，而不是最终产品。

### 2.2 规则蒸馏到小网络（本机采用）

- 结构 68 → 192 → 96 → 11 全连接，ReLU，32,843 个参数（约 129 KB），纯 Java 推理。
- 输入 68 维：音高、时值、前后间隔、歌词音素数、跳进、拍点位置（强拍/弱拍/反拍）、速度、风格 one-hot 等；输出 11 维，乘每维尺度得到参数偏移。
- 训练：167,151 条音符样本，全批量 Adam（lr 2e-3），34 epoch，验证集 1/12；训练损失 0.00280、验证损失 0.00290。
- 物理量误差（验证集，反归一化后）：DYN 1.68（0-127）、BRE 0.42、BRI 0.32、CLE 0.54、OPE 0.34、POR 2.15（约 4 ms）、VIB 1.10（约 8 音分）、PIT 前段 54.99 unit（约 1.3 音分）、后段 28.51 unit、力度 0.66、GEN 0.22。
- 选择理由：参数比 0.8B 小四个数量级；单线程 CPU 每音轨几十毫秒；完全离线；对每个输出维度都可做物理量校验。上下文信息用「手工特征 + 前后间隔」近似，而不是堆长序列模型。

### 2.3 序列模型（未采用，留作后续）

LSTM / TCN / 小型 Transformer 能建模更长上下文（乐句走向、重复段落），但 1-5M 参数对中端机意味着更长的加载和推理；而且没有人工标注数据时，长上下文学到的仍是教师规则的平滑版本。若要升级，优先 TCN（1-5M）而不是 Transformer。

### 2.4 端到端歌声合成（未采用）

DiffSinger / VISinger / 类 SVS 模型上限高，但通常是 10M-100M+ 参数、需要音素对齐与训练数据、推理以秒计；与「APK 无权重、中端机实时」冲突。保持现有 DSP 合成器 + 表情曲线是更稳的路线。

### 2.5 音色克隆 / 转换（未采用）

so-vits-svc / RVC 类需要目标歌手数据，体积、延迟、版权风险都不符合当前产品形态；BriNeting 已经用「频谱规律」而非音频克隆实现多声库能力。

## 3. 原生支持音频输入的方案

目标：不训练新声学模型，只从干声提取「怎么唱」，搬到工程里。

| 方案 | 精度 | 成本 | 结论 |
| --- | --- | --- | --- |
| YIN / pYIN（自相关 + 抛物线插值） | 干净人声 ±几音分 | 纯 Java，零下载，实时 | **v10.1 采用** |
| CREPE / CREPE-tiny（CNN 音高） | 更高，抗噪更好 | 约 0.5-1M 参数，需 TFLite/模型下载 | 可选高精度模式（后续） |
| RMVPE / SWIPE / torchcrepe | 高 | 依赖重、移植成本高 | 不采用 |
| WORLD / Harvest / DIO | 音高 + 谱包络 | 分析-重合成，Java 移植大 | 不采用 |
| SPICE / 自监督模型 | 高 | 需 GPU/NNAPI | 不采用 |

实现要点（`app/src/com/dsh/v4tune/ai/AudioTune.java`，纯 Java）：

- 44.1 kHz 降到 11.025 kHz（box 均值），20 ms 帧移、60 ms 窗；YIN 差分函数 + 累积均值归一化，先取谷值再用归一化自相关做抛物线插值（直接在差分函数上插值会有 ±20-90 音分噪声）。
- RMS 逐帧、-55 dB 以下视为静音；浊音帧不足 12 帧时报「检测不到足够的嗓音帧」。
- 按工程的音符时间表切片：头段（前 0.07s 或 35%）、中段、尾段；剔除偏离中位 >180 音分的帧。
- 输出：PIT 四点式（起始滑音、主音高、尾段、释放），DYN 用 dB 相对中位响度，VIB 只在长音（≥480 tick）且振幅 >6 音分时写。
- 单位：PBS 视为 2 半音，`PIT_UNIT = 8192/200 = 40.96 unit/音分`；这与旧 v1 把音分直接当 unit 写（1 音分 ≈ 0.024 unit，几乎听不出来）是 v10.1 修掉的关键 bug。

## 4. 自测与证据

### 4.1 真实工程统计

HUG.vsqx（Yamaha VSQX4，824 音符、4 个 vsPart）：

- part0：639 个控制器事件（DYN 393 / TRE 228 / BRE 13 / OPE 5）；
- part1：968 个（DYN 936 / 弯音轮 17 / TRE 15）；
- part2/3 无控制器；
- 该工程没有 PIT/PBS，所以真实数据能直接对照的只有 DYN/BRE，音高类规则只能靠合成信号验证。

### 4.2 桌面合成信号

用连续相位合成 5 个音（C4 E4 G4 E4 C4，带 2/3 次谐波），分别 detune = 0 与 +30 音分，跑 AudioTune 后检查曲线：0 时中段 PIT 1-2 unit、首音 -291、末音 -637；+30 音分时中段 1224-1230 unit、末音 593，VIB 写 (1440, 68)/(2400, 67)，与 30×40.96≈1229 一致。

### 4.3 真机（LDPlayer，v10.1 构建）

- 测试工程 5 音符 / 120 BPM；WAV 198 帧、浊音 89%。
- 报告：平均音准偏差 30 音分，写入 PIT 20 点 / DYN 15 点 / VIB 2 点，共 37 处。
- 撤销后 PIT 回到 0 线，重做恢复，说明写入了撤销栈。
- 导出 WAV 做基频对比（取每音符中段 120 ms）：

  | 音符 | 未调音（音分，相对十二平均律） | 调音后（音分） |
  | --- | --- | --- |
  | C4 | -2.1 | +27.5 |
  | E4 | -1.9 | +28.1 |
  | G4 | -7.5 | +22.6 |
  | E4 | -7.2 | +22.0 |
  | C4 | -2.2 | +28.3 |

  差值 25-30 音分，证明 PIT 曲线真的作用到了渲染器，而不只是写进 JSON。

## 5. 与 0.8B 约束的距离

- 本机模型：32,843 参数 ≈ 0.033M，占 0.8B 的 0.004%。
- 即使后续加 CREPE-tiny（约 0.5M）和 TCN（1-5M），总量仍 <10M，远低于 0.8B。
- 真正占空间的是音频与声库，不是调音网络。

## 6. 限制与后续

- AudioTune 只适用于单声部干声；伴奏、合唱、强转音、气声/假声会失败或偏差大；需要先把工程与音频对齐，否则报告会虚高（本次实测错位时是 456 音分）。
- YIN 搜索 65-1000 Hz；VIB 只写在长音；没有「颤音渐入曲线」，只有单点振幅。
- 教师规则没有人工标注数据做监督，验证集只能证明「网络逼近教师」，不能证明「教师等于好听的调音」；这是下一步最该补的数据。
- 可选的下一步：CREPE-tiny 作为高精度音高分析（下载式，~2 MB）；TCN 上下文模型；用真实工程里用户手画的 DYN/BRE 当弱监督。

## 7. 复现

- 训练：`aimodel/train_local_tuner_v2.py` → `aimodel/britune-v2.bin` + `britune-v2.json`。
- 端侧推理：`app/src/com/dsh/v4tune/ai/LocalTuner.java`；单位换算和 PIT 四点式在同文件 `tune()`。
- 音频分析：`app/src/com/dsh/v4tune/ai/AudioTune.java`；入口 `MainActivity.audioTuneMenu()`。
- 模型清单：`aimodel/local-model.json`（version 2 / 131,984 B / sha256 0950cf50…）。
