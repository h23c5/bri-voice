【0】三分钟上手 + 新手引导
  第一次启动会自动出现 6 步「新手引导」：每一步用高亮框和箭头指出按钮位置：
    新建 → 打开 → 声库 → 播放 → 导出WAV → 工具
  点「下一步」走完，点「跳过」关闭；之后随时可以在 工具 → 新手引导（图标指引）重看。
  1) 工具菜单 → 声库 → 确认已安装内置声库（首次启动会自动装）
  2) 打开一个 .vsqx / .ustx / .ust 工程，或新建后自己画音符
  3) 点『从头播放』——先出声再继续渲染，不必等整首
  4) 满意后点『导出WAV』

【1】界面与工具菜单
  顶部工具条：新建 / 打开 / 保存 / 另存为 / 导出WAV / 撤销 / 重做 / 示例 / 声库 / 关于。
  『工具』菜单里集中了不常用的功能：
    语言（中/英/日）· 混音器 · 插件 · 导入音频到轨道 · 歌词填充 ·
    音符合并检测 · 播放设备 · 音频片段列表 · 手动切换横竖屏 · AI 助手 ·
    设置 · 检查更新 · 制作声库 · 教程 · 新手引导（图标指引）
  左侧是琴键与音名；右侧是参数轨选择（DYN/PIT/VIB…）。

【2】工程与文件
  · 支持 .vsqx（VOCALOID4 / VOCALOID3）、.vsq（VOCALOID2）、.mid，
    以及 OpenUtau 的 .ustx、UTAU 的 .ust（导入 / 导出）
  · 保存/另存为会保持原架构；导出给电脑端时建议保持 .vsqx
  · 也能在文件管理器里『用 BriVoice 打开』这些文件
  · 工程默认放在 /sdcard/BriVoice_root/projects/

【3】钢琴卷帘
  · 新建音符：在空白处点一下
  · 拖动：按住音符中部移动位置/音高；拖右边缘改时长；拖左边缘改力度
  · 删除：长按音符
  · 歌词：选中音符后在歌词框输入；支持拼音（luo）、汉字（内置两万余字拼音表）、假名
  · 缩放：双指捏合；吸附：左上『吸附』开关
  · 撤销/重做：工具条按钮，24 步

【4】参数曲线
  在右侧参数轨里选择参数，然后在轨道上画：
    DYN 力度 · BRE 呼吸 · BRI 明亮 · CLE 清晰 · OPE 张口 · GEN 性别 ·
    POR 滑音时间 · PIT 音高偏移 · PBS 弯音敏感 · VIB 颤音深度 · XSY 交叉合成 · GWL 咆哮
  画笔/直线/选择三种工具（需要时在参数轨上切换）。
  · 默认带一点颤音（22 音分、5.3 Hz、延迟 0.22 秒）；把 VIB 拉到 0 可关闭
  · PIT 是相对音高，配合 PBS 使用；滑音由 POR 控制

【5】播放、实时渲染与同步
  · 『播放』『从头播放』采用边渲染边播放：先出约 1 秒即出声，其余在后台继续
  · 播放头随声音同步移动，卷帘会自动滚动跟随播放头（设置里可关）
  · 播放头可拖动定位；听到的和看到的对不上时，用『指针延迟补偿』

【6】导出 WAV
  44.1 kHz / 16 bit / 立体声；导出到 /sdcard/BriVoice_root/export/
  长工程导出需要时间，导出时可继续操作界面。

【7】多轨与混音器、插件
  · 工程可含多轨，逐轨渲染后混合
  · 混音器：每轨音量、声像、静音/独奏
  · 插件：内置三种（混响 / 合唱 / 压缩），可作用于每轨
  · 每轨可以单独选择歌姬（声库）

【8】音频轨（伴奏）
  · 工具菜单 →『导入音频到轨道』选一个 WAV
  · 可在卷帘里拖动对齐；导出时可与歌声混合
  · 音频片段列表可管理已导入的片段

【9】声库：导入与制作（重点）

  9.1 导入现成的 .v4voice
    工具菜单 → 声库 → 导入声库文件（.v4voice），选一个文件即可。
    内置声库在首次启动时自动安装到 /sdcard/BriVoice_root/voicebanks/ 。

  9.2 导入 UTAU 声库（oto.ini / zip）
    工具菜单 → 声库 → 导入 UTAU 声库（oto.ini）。
    · 可以直接选 UTAU 声库的 .zip；也可以点「浏览」选文件夹
    · 文件夹里没有 oto.ini 也没关系：会自动往下找 4 层
      （常见结构 voice/<声库名>/oto.ini 可直接导入）
    · 文件名支持 UTF-8 / Shift_JIS / GBK；压缩包会按这三种编码依次尝试
    · WAV 支持 8 / 16 / 24 bit PCM 与 32-bit float
    · 选「导入声库文件」时如果选到的是 UTAU zip，也会自动转到这个流程
    转换只测量元音、辅音起始段与谐波包络，不保存原始录音。
    如果失败，提示会给出 oto 条目数、缺失/无法解析的 wav 数量，便于排查。
    注意：当前只按元音（a/i/u/e/o）建库，元音以外的别名不会单独成库；
    多音阶（CVVC / VCV / 多 pitch）声库会取各自能测到的样本，不区分音阶。

  9.3 手机端制作声库（从你自己的 VOCALOID4 声库转换）
    包内只有『测量得到的频谱统计量』：谐波包络、共振峰、辅音噪声谱、帧序列。
    不含任何原始录音，全程离线。

    准备：电脑端声库是一个文件夹，形如
       BK8H76TAEHXWSKDB/
           Luotianyi_CHN_Meng.ddb    ← 帧数据（必须有）
           Luotianyi_CHN_Meng.ddi    ← 音素表
           *.vvd                     ← 声库标识（音色 id / 名称）
    把整个文件夹拷到手机，例如 /sdcard/VoiceDB/BK8H76TAEHXWSKDB/ 。

    步骤：
      1) 工具菜单 →『制作声库』
      2) 点『浏览…』找到那个声库文件夹（也可以直接填路径），选到文件夹为止
      3) 填声库名称（如『洛天依 BV』），留空则用文件夹名
      4) 点『开始转换』并等待（电脑约 20 秒，手机通常几分钟）
          这个向导同时支持 .ddb 与 oto.ini，会自动判断
      5) 完成后提示文件名与大小，位置 /sdcard/BriVoice_root/voicebanks/<名称>.v4voice
         应用会自动识别，可直接在卷帘里试听

    为什么有些音素没有：转换器只写『确实测量到』的东西，测不到就留空，
    由应用回退到内置表——刻意如此，避免编造。『辅音少』通常不是故障。

  9.4 给电脑端用
    若要导出工程给电脑端 VOCALOID 打开，请确认声库识别信息正确：
    应用会写入 vVoice 的 id / name / bs / pc。若电脑端提示『没有数据』，
    通常是这几项与实际安装的声库不匹配（见 docs/voicebank-port-spec.md）。

【10】自动保存与恢复
  · 默认开启，每 60 秒检查一次；设置里可关闭或改成 15 / 30 / 60 / 120 / 300 秒
  · 只在上次保存之后有改动时才写，不会一直占 IO
  · 已另存的工程写回原文件；未另存的工程写到
      /sdcard/BriVoice_root/projects/<工程名>.vsqx
  · 切到后台时会补存一次；状态栏会显示『已自动保存 时:分:秒』
  · 自动保存失败会在状态栏提示原因（权限、空间等），不会静默吞掉

【11】检查更新
  启动约 2.5 秒后自动检查一次（静默）；也可手动：工具菜单 →『检查更新』。
  有新版本会弹出说明与『下载并安装』，下载完成校验 SHA-256 后交给系统安装。
  更新清单来自 gitee.com/h23c5/bri-voice 的 update.json。

【12】设置项说明
  · 自动保存 / 自动保存间隔：见第 10 节
  · 合成方式：
      声库谐波（还原，默认）——使用声库实测的谐波与噪声，音色最接近原声库
      网页快速（共振峰，省电）——跳过实测谐波，只用共振峰模型，
        更快、更省电，风格接近网页版 BriVoice
  · 音色（网页预设）：跟随声库 / 明亮 / 柔和 / 低语；只在共振峰路径上生效
  · 播放时滚动跟随（同步）：播放时卷帘自动跟随播放头；关掉可手动拖动查看
  · 音素锁定：锁定当前音符的音素，不被歌词改动影响
  · 指针延迟补偿：-2500 ～ +2500 ms，对齐『听到的』与『看到的』
  · 实测辅音噪声：使用声库测得的辅音噪声谱（默认关闭；开启后更真实，
    但个别设备上曾出现杂音，故默认关闭）
  · 噪声强度：上面那项的强度 0～200%
  · 帧序列合成：用真实帧序列合成（默认关闭，实验性）

【13】AI 助手与外部接口（实验）
  默认关闭。开启后需要你自己填一个 OpenAI 兼容接口地址与密钥（只存在本机）。
  用途：用自然语言让 AI 修改参数曲线与节奏。
  另有本机 127.0.0.1 外部接口，供脚本控制（详见仓库文档）。

【14】常见问题与排错
  Q: 播放头和声音对不上
  A: 设置 → 指针延迟补偿，边听边调，直到对齐。
  Q: 歌声里出现电流音/杂音
  A: 检查『实测辅音噪声』是否被打开；关闭它、或把噪声强度调低。
  Q: 导出很久没完成
  A: 长工程正常；保持应用在前台，必要时关闭其它应用。
  Q: UTAU 声库导入失败
  A: 看提示里的 oto 条目数和缺失 wav 数。常见原因：选到了上级目录（会自动找 4 层，
     仍找不到就选 oto.ini 所在目录）、压缩包编码特殊（程序会试 UTF-8 / Shift_JIS / GBK）、
     或 wav 损坏。可以直接选 zip，让程序解压。
  Q: UTAU 导入后辅音少 / 没有某些音
  A: 见 9.2 / 9.3：只写实际测到的数据，没测到就回退内置表。
  Q: 制作声库提示『找不到该文件夹』
  A: 路径写错或没选到文件夹。用『浏览…』最稳；注意别选到 .ddb 文件。
  Q: 制作声库提示『该文件夹里没有 .ddb 文件』
  A: 层级不对或拷贝不完整；声库文件夹里必须有 .ddb 或 oto.ini。
  Q: 更新检查提示无法连接 / HTTP 404
  A: 说明更新清单还没发布或网络不通；确认仓库上存在 update.json。
  Q: 导入工程后没有音符
  A: 可能是文件架构不受支持或该工程本来为空；也可能是声库不匹配（见 9.4）。
  Q: 能把生成的 .v4voice 分享出去吗
  A: 不建议。它是你已授权声库的派生数据，请自行确认授权范围。

【15】数据与隐私
  · 工程、声库、导出文件都保存在本机 /sdcard/BriVoice_root/
  · 联网只发生在三处：检查更新（读 Gitee 上的清单）、你自己开启的 AI 接口，
    以及你主动从浏览器下载声库（不经过本应用）
  · 除此之外不上传任何数据
  · 本应用与 VOCALOID、Yamaha 及其关联公司无关；内置声库为参数化派生数据

【16】AI 助手：复制提示词、JSON 与云端保存
16.1 工具 → AI 调音
  · 填写接口地址 / 模型 / API Key（OpenAI 兼容），打开「启用 AI 自动调参」
  · 也可以完全不用接口，走下面的复制提示词流程
16.2 复制提示词
  · 在「要求」里写自然语言（可空），点「复制提示词」
  · 粘贴到任意 AI 对话框；提示词已包含规则、音符和现有参数，要求只回 JSON
  · 把 AI 的答复贴到「输出 JSON」框，点「应用 JSON」
16.3 输出 JSON
  · 框里可直接编辑；点「应用 JSON」只改 JSON 列出的参数/音符
  · 「导出 JSON 文件」写到 /sdcard/BriVoice_root/export/ai/ai-时间.json
16.4 云端保存（用你自己的后端）
  · 填完整 URL；Token 可选，会以 Authorization: Bearer 发送
  · 保存：POST {"format":"brivoice-project-v1","name":...,"project":"<VSQX>"}
  · 读取：GET 同一 URL，返回 {"project":"<VSQX>"} 即可；读取会替换当前工程（可撤销）
  · App 不连接任何 BriVoice 官方服务器，地址和 Token 只保存在本机

【17】角色立绘（左下角）
17.1 放一张立绘
  · 工具 → 设置 → 角色立绘 → 选择图片…
  · 白底图片会自动去掉背景；只删和边缘连通的白色，衣服/高光里的白色会保留
  · 透明 PNG 直接使用，不再抠图
  · 「清除立绘」随时移除
17.2 调整
  · 透明度滑块：0%（看不见）到 100%
  · 大小滑块：约 8%–60% 的钢琴卷帘宽度
  · 立绘只显示在左下角，不挡按钮，也不影响播放
17.3 保存
  · 图片处理后存在 App 私有目录 files/character.png
  · 下次启动自动恢复，透明度和大小也会记住

【18】zip 声库装不上怎么办（8.1.1）
18.1 先看详细报错
  · 导入失败会弹出「压缩包无法识别」或「声库生成失败」
  · 里面会列出：URI/文件名/大小、UTF-8 / Shift_JIS / GBK 三次解压结果、
    oto.ini 条目数、文件名匹配数、压缩包内文件样本、Android/机型/App 版本
  · 点「复制日志」直接复制整段，粘贴到反馈里即可
  · 日志也会写到 BriVoice_root/last_voicebank_error.txt
18.2 8.1.1 已做的兼容修复
  · Windows 打包的 zip 用反斜杠路径：自动换成 /
  · 声库文件放在子目录（如 bank/wav/a.wav）：递归查找采样
  · oto.ini 编码：UTF-8 / Shift_JIS / GBK / UTF-16（带 BOM）
  · oto.ini 只有 CR 换行：也能解析
  · zip 里直接放的是 .v4voice：自动解压并导入，不再要求 oto.ini
  · 按 oto.ini 与实际文件名的匹配度选择 zip 编码，避免文件名乱码后找不到采样
18.3 还是失败时
  · 确认 zip 里确实有 oto.ini 和 wav 采样（或一个 .v4voice）
  · 带密码、分卷、7z 改后缀的压缩包不支持，请重新打成普通 zip
  · 把「复制日志」的内容发出来，就能定位到具体是哪个文件/编码/条目出错

【19】USTX / UST 工程打开后看不到音符或歌词（8.1.2）
19.1 OpenUTAU .ustx
  · 正确读取 voice_parts、track_no、part.position 和每个 part 的 notes
  · 多轨工程按 track_no 放回对应音轨；不会再全塞进最后一轨导致第一轨空白
  · note 的 tone / duration / lyric（单数）都读，歌词不再丢
  · 打开工程后会自动把钢琴卷帘的纵向范围滚到音符所在音高
19.2 UTAU .ust
  · Lyric / Length / NoteNum / Velocity 改为大小写不敏感，值会去掉首尾空格
  · 歌词按音符顺序一一对应；R 休止仍然跳过
19.3 如果歌词还是空
  · 用文本编辑器确认每个 [#0001] 段里有 Lyric=... 行
  · 如果是 OpenUTAU 的 .ustx，确认 note 里是 lyric: 而不是自定义字段
  · 把工程文件发出来即可按实际结构补解析

【20】zip 报 MALFORMED[1]（8.1.3）
20.1 原因
  · 这不是压缩包坏了，而是 Java 的 zip 读取器要求文件名是 UTF-8；
    有些 Windows/日文工具打的包把 Shift_JIS/GBK 文件名标成了 UTF-8，Java 直接抛 MALFORMED[1]
20.2 现在的处理
  · 先按正常方式解压；失败就切到自写的容错解压器，逐个读本地文件头
  · 文件名用替换字符解码，不因为一个坏文件名放弃整个声库
  · 仍会按 UTF-8 / Shift_JIS / GBK 尝试，并按 oto.ini 与实际 wav 的匹配度选最合适的一种
  · 声库识别也改成扫原始文件名，坏 zip 也会被送到 UTAU 导入流程，而不是误当成 .v4voice
20.3 如果还失败
  · 错误窗口里会同时给正常解压和容错解压的错误，点「复制日志」发出来
  · 分卷、加密、7z 改后缀仍不支持
