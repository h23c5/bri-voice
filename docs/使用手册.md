【0】三分钟上手 + 新手引导
  第一次启动会自动出现 6 步「新手引导」：每一步用高亮框和箭头指出按钮位置：
    新建 → 打开 → 声库 → 播放 → 导出WAV → 工具
  点「下一步」走完，点「跳过」关闭；之后随时可以在 工具 → 新手引导（图标指引）重看。
  1) 工具菜单 → 声库 → 确认已安装内置声库（首次启动会自动装）
  2) 打开一个 .vsqx / .ustx / .ust 工程，或新建后自己画音符
  3) 点『从头播放』——先出声再继续渲染，不必等整首
  4) 满意后点『导出WAV』

【1】界面与工具菜单
  顶部工具条：新建 / 打开 / 保存 / 另存为 / 导出WAV / 撤销 / 重做 / 示例 / 声库 / 关于。
  『工具』菜单里集中了不常用的功能：
    语言（中/英/日）· 混音器 · 插件 · 导入音频到轨道 · 歌词填充 ·
    音符合并检测 · 播放设备 · 音频片段列表 · 手动切换横竖屏 · AI 助手 ·
    设置 · 检查更新 · 制作声库 · 教程 · 新手引导（图标指引）
  左侧是琴键与音名；右侧是参数轨选择（DYN/PIT/VIB…）。

【2】工程与文件
  · 支持 .vsqx（VOCALOID4 / VOCALOID3）、.vsq（VOCALOID2）、.mid，
    以及 OpenUtau 的 .ustx、UTAU 的 .ust（导入 / 导出）
  · 保存/另存为会保持原架构；导出给电脑端时建议保持 .vsqx
  · 也能在文件管理器里『用 BriVoice 打开』这些文件
  · 工程默认放在 /sdcard/BriVoice_root/projects/

【3】钢琴卷帘
  · 新建音符：在空白处点一下
  · 拖动：按住音符中部移动位置/音高；拖右边缘改时长；拖左边缘改力度
  · 删除：长按音符
  · 歌词：选中音符后在歌词框输入；支持拼音（luo）、汉字（内置两万余字拼音表）、假名
  · 缩放：双指捏合；吸附：左上『吸附』开关
  · 撤销/重做：工具条按钮，24 步

【4】参数曲线
  在右侧参数轨里选择参数，然后在轨道上画：
    DYN 力度 · BRE 呼吸 · BRI 明亮 · CLE 清晰 · OPE 张口 · GEN 性别 ·
    POR 滑音时间 · PIT 音高偏移 · PBS 弯音敏感 · VIB 颤音深度 · XSY 交叉合成 · GWL 咆哮
  画笔/直线/选择三种工具（需要时在参数轨上切换）。
  · 默认带一点颤音（22 音分、5.3 Hz、延迟 0.22 秒）；把 VIB 拉到 0 可关闭
  · PIT 是相对音高，配合 PBS 使用；滑音由 POR 控制

【5】播放、实时渲染与同步
  · 『播放』『从头播放』采用边渲染边播放：先出约 1 秒即出声，其余在后台继续
  · 播放头随声音同步移动，卷帘会自动滚动跟随播放头（设置里可关）
  · 播放头可拖动定位；听到的和看到的对不上时，用『指针延迟补偿』

【6】导出 WAV
  44.1 kHz / 16 bit / 立体声；导出到 /sdcard/BriVoice_root/export/
  长工程导出需要时间，导出时可继续操作界面。

【7】多轨与混音器、插件
  · 工程可含多轨，逐轨渲染后混合
  · 混音器：每轨音量、声像、静音/独奏
  · 插件：内置三种（混响 / 合唱 / 压缩），可作用于每轨
  · 每轨可以单独选择歌姬（声库）

【8】音频轨（伴奏）
  · 工具菜单 →『导入音频到轨道』选一个 WAV
  · 可在卷帘里拖动对齐；导出时可与歌声混合
  · 音频片段列表可管理已导入的片段

【9】声库：导入与制作（重点）

  9.1 导入现成的 .v4voice
    工具菜单 → 声库 → 导入声库文件（.v4voice），选一个文件即可。
    内置声库在首次启动时自动安装到 /sdcard/BriVoice_root/voicebanks/ 。

  9.2 导入 UTAU 声库（oto.ini / zip）
    工具菜单 → 声库 → 导入 UTAU 声库（oto.ini）。
    · 可以直接选 UTAU 声库的 .zip；也可以点「浏览」选文件夹
    · 文件夹里没有 oto.ini 也没关系：会自动往下找 4 层
      （常见结构 voice/<声库名>/oto.ini 可直接导入）
    · 文件名支持 UTF-8 / Shift_JIS / GBK；压缩包会按这三种编码依次尝试
    · WAV 支持 8 / 16 / 24 bit PCM 与 32-bit float
    · 选「导入声库文件」时如果选到的是 UTAU zip，也会自动转到这个流程
    转换只测量元音、辅音起始段与谐波包络，不保存原始录音。
    如果失败，提示会给出 oto 条目数、缺失/无法解析的 wav 数量，便于排查。
    注意：当前只按元音（a/i/u/e/o）建库，元音以外的别名不会单独成库；
    多音阶（CVVC / VCV / 多 pitch）声库会取各自能测到的样本，不区分音阶。

  9.3 手机端制作声库（从你自己的 VOCALOID4 声库转换）
    包内只有『测量得到的频谱统计量』：谐波包络、共振峰、辅音噪声谱、帧序列。
    不含任何原始录音，全程离线。

    准备：电脑端声库是一个文件夹，形如
       BK8H76TAEHXWSKDB/
           Luotianyi_CHN_Meng.ddb    ← 帧数据（必须有）
           Luotianyi_CHN_Meng.ddi    ← 音素表
           *.vvd                     ← 声库标识（音色 id / 名称）
    把整个文件夹拷到手机，例如 /sdcard/VoiceDB/BK8H76TAEHXWSKDB/ 。

    步骤：
      1) 工具菜单 →『制作声库』
      2) 点『浏览…』找到那个声库文件夹（也可以直接填路径），选到文件夹为止
      3) 填声库名称（如『洛天依 BV』），留空则用文件夹名
      4) 点『开始转换』并等待（电脑约 20 秒，手机通常几分钟）
          这个向导同时支持 .ddb 与 oto.ini，会自动判断
      5) 完成后提示文件名与大小，位置 /sdcard/BriVoice_root/voicebanks/<名称>.v4voice
         应用会自动识别，可直接在卷帘里试听

    为什么有些音素没有：转换器只写『确实测量到』的东西，测不到就留空，
    由应用回退到内置表——刻意如此，避免编造。『辅音少』通常不是故障。

  9.4 给电脑端用
    若要导出工程给电脑端 VOCALOID 打开，请确认声库识别信息正确：
    应用会写入 vVoice 的 id / name / bs / pc。若电脑端提示『没有数据』，
    通常是这几项与实际安装的声库不匹配（见 docs/voicebank-port-spec.md）。

【10】自动保存与恢复
  · 默认开启，每 60 秒检查一次；设置里可关闭或改成 15 / 30 / 60 / 120 / 300 秒
  · 只在上次保存之后有改动时才写，不会一直占 IO
  · 已另存的工程写回原文件；未另存的工程写到
      /sdcard/BriVoice_root/projects/<工程名>.vsqx
  · 切到后台时会补存一次；状态栏会显示『已自动保存 时:分:秒』
  · 自动保存失败会在状态栏提示原因（权限、空间等），不会静默吞掉

【11】检查更新
  启动约 2.5 秒后自动检查一次（静默）；也可手动：工具菜单 →『检查更新』。
  有新版本会弹出说明与『下载并安装』，下载完成校验 SHA-256 后交给系统安装。
  更新清单来自 gitee.com/h23c5/bri-voice 的 update.json。

【12】设置项说明
  · 自动保存 / 自动保存间隔：见第 10 节
  · 合成方式：
      声库谐波（还原，默认）——使用声库实测的谐波与噪声，音色最接近原声库
      网页快速（共振峰，省电）——跳过实测谐波，只用共振峰模型，
        更快、更省电，风格接近网页版 BriVoice
  · 音色（网页预设）：跟随声库 / 明亮 / 柔和 / 低语；只在共振峰路径上生效
  · 播放时滚动跟随（同步）：播放时卷帘自动跟随播放头；关掉可手动拖动查看
  · 音素锁定：锁定当前音符的音素，不被歌词改动影响
  · 指针延迟补偿：-2500 ～ +2500 ms，对齐『听到的』与『看到的』
  · 实测辅音噪声：使用声库测得的辅音噪声谱（默认关闭；开启后更真实，
    但个别设备上曾出现杂音，故默认关闭）
  · 噪声强度：上面那项的强度 0～200%
  · 帧序列合成：用真实帧序列合成（默认关闭，实验性）

【13】AI 助手与外部接口（实验）
  默认关闭。开启后需要你自己填一个 OpenAI 兼容接口地址与密钥（只存在本机）。
  用途：用自然语言让 AI 修改参数曲线与节奏。
  另有本机 127.0.0.1 外部接口，供脚本控制（详见仓库文档）。

【14】常见问题与排错
  Q: 播放头和声音对不上
  A: 设置 → 指针延迟补偿，边听边调，直到对齐。
  Q: 歌声里出现电流音/杂音
  A: 检查『实测辅音噪声』是否被打开；关闭它、或把噪声强度调低。
  Q: 导出很久没完成
  A: 长工程正常；保持应用在前台，必要时关闭其它应用。
  Q: UTAU 声库导入失败
  A: 看提示里的 oto 条目数和缺失 wav 数。常见原因：选到了上级目录（会自动找 4 层，
     仍找不到就选 oto.ini 所在目录）、压缩包编码特殊（程序会试 UTF-8 / Shift_JIS / GBK）、
     或 wav 损坏。可以直接选 zip，让程序解压。
  Q: UTAU 导入后辅音少 / 没有某些音
  A: 见 9.2 / 9.3：只写实际测到的数据，没测到就回退内置表。
  Q: 制作声库提示『找不到该文件夹』
  A: 路径写错或没选到文件夹。用『浏览…』最稳；注意别选到 .ddb 文件。
  Q: 制作声库提示『该文件夹里没有 .ddb 文件』
  A: 层级不对或拷贝不完整；声库文件夹里必须有 .ddb 或 oto.ini。
  Q: 更新检查提示无法连接 / HTTP 404
  A: 说明更新清单还没发布或网络不通；确认仓库上存在 update.json。
  Q: 导入工程后没有音符
  A: 可能是文件架构不受支持或该工程本来为空；也可能是声库不匹配（见 9.4）。
  Q: 能把生成的 .v4voice 分享出去吗
  A: 不建议。它是你已授权声库的派生数据，请自行确认授权范围。

【15】数据与隐私
  · 工程、声库、导出文件都保存在本机 /sdcard/BriVoice_root/
  · 联网只发生在三处：检查更新（读 Gitee 上的清单）、你自己开启的 AI 接口，
    以及你主动从浏览器下载声库（不经过本应用）
  · 除此之外不上传任何数据
  · 本应用与 VOCALOID、Yamaha 及其关联公司无关；内置声库为参数化派生数据

【16】AI 助手：复制提示词、JSON 与云端保存
16.1 工具 → AI 调音
  · 填写接口地址 / 模型 / API Key（OpenAI 兼容），打开「启用 AI 自动调参」
  · 也可以完全不用接口，走下面的复制提示词流程
16.2 复制提示词
  · 在「要求」里写自然语言（可空），点「复制提示词」
  · 粘贴到任意 AI 对话框；提示词已包含规则、音符和现有参数，要求只回 JSON
  · 把 AI 的答复贴到「输出 JSON」框，点「应用 JSON」
16.3 输出 JSON
  · 框里可直接编辑；点「应用 JSON」只改 JSON 列出的参数/音符
  · 「导出 JSON 文件」写到 /sdcard/BriVoice_root/export/ai/ai-时间.json
16.4 云端保存（用你自己的后端）
  · 填完整 URL；Token 可选，会以 Authorization: Bearer 发送
  · 保存：POST {"format":"brivoice-project-v1","name":...,"project":"<VSQX>"}
  · 读取：GET 同一 URL，返回 {"project":"<VSQX>"} 即可；读取会替换当前工程（可撤销）
  · App 不连接任何 BriVoice 官方服务器，地址和 Token 只保存在本机

【17】角色立绘（左下角）
17.1 放一张立绘
  · 工具 → 设置 → 角色立绘 → 选择图片…
  · 白底图片会自动去掉背景；只删和边缘连通的白色，衣服/高光里的白色会保留
  · 透明 PNG 直接使用，不再抠图
  · 「清除立绘」随时移除
17.2 调整
  · 透明度滑块：0%（看不见）到 100%
  · 大小滑块：约 8%–60% 的钢琴卷帘宽度
  · 立绘只显示在左下角，不挡按钮，也不影响播放
17.3 保存
  · 图片处理后存在 App 私有目录 files/character.png
  · 下次启动自动恢复，透明度和大小也会记住

【18】zip 声库装不上怎么办（8.1.1）
18.1 先看详细报错
  · 导入失败会弹出「压缩包无法识别」或「声库生成失败」
  · 里面会列出：URI/文件名/大小、UTF-8 / Shift_JIS / GBK 三次解压结果、
    oto.ini 条目数、文件名匹配数、压缩包内文件样本、Android/机型/App 版本
  · 点「复制日志」直接复制整段，粘贴到反馈里即可
  · 日志也会写到 BriVoice_root/last_voicebank_error.txt
18.2 8.1.1 已做的兼容修复
  · Windows 打包的 zip 用反斜杠路径：自动换成 /
  · 声库文件放在子目录（如 bank/wav/a.wav）：递归查找采样
  · oto.ini 编码：UTF-8 / Shift_JIS / GBK / UTF-16（带 BOM）
  · oto.ini 只有 CR 换行：也能解析
  · zip 里直接放的是 .v4voice：自动解压并导入，不再要求 oto.ini
  · 按 oto.ini 与实际文件名的匹配度选择 zip 编码，避免文件名乱码后找不到采样
18.3 还是失败时
  · 确认 zip 里确实有 oto.ini 和 wav 采样（或一个 .v4voice）
  · 带密码、分卷、7z 改后缀的压缩包不支持，请重新打成普通 zip
  · 把「复制日志」的内容发出来，就能定位到具体是哪个文件/编码/条目出错

【19】USTX / UST 工程打开后看不到音符或歌词（8.1.2）
19.1 OpenUTAU .ustx
  · 正确读取 voice_parts、track_no、part.position 和每个 part 的 notes
  · 多轨工程按 track_no 放回对应音轨；不会再全塞进最后一轨导致第一轨空白
  · note 的 tone / duration / lyric（单数）都读，歌词不再丢
  · 打开工程后会自动把钢琴卷帘的纵向范围滚到音符所在音高
19.2 UTAU .ust
  · Lyric / Length / NoteNum / Velocity 改为大小写不敏感，值会去掉首尾空格
  · 歌词按音符顺序一一对应；R 休止仍然跳过
19.3 如果歌词还是空
  · 用文本编辑器确认每个 [#0001] 段里有 Lyric=... 行
  · 如果是 OpenUTAU 的 .ustx，确认 note 里是 lyric: 而不是自定义字段
  · 把工程文件发出来即可按实际结构补解析

【20】zip 报 MALFORMED[1]（8.1.3）
20.1 原因
  · 这不是压缩包坏了，而是 Java 的 zip 读取器要求文件名是 UTF-8；
    有些 Windows/日文工具打的包把 Shift_JIS/GBK 文件名标成了 UTF-8，Java 直接抛 MALFORMED[1]
20.2 现在的处理
  · 先按正常方式解压；失败就切到自写的容错解压器，逐个读本地文件头
  · 文件名用替换字符解码，不因为一个坏文件名放弃整个声库
  · 仍会按 UTF-8 / Shift_JIS / GBK 尝试，并按 oto.ini 与实际 wav 的匹配度选最合适的一种
  · 声库识别也改成扫原始文件名，坏 zip 也会被送到 UTAU 导入流程，而不是误当成 .v4voice
20.3 如果还失败
  · 错误窗口里会同时给正常解压和容错解压的错误，点「复制日志」发出来
  · 分卷、加密、7z 改后缀仍不支持


【21】音高曲线（8.2）
21.1 你会看到什么
  · 每个音符中心有一个小圆点，位置就是这个音符实际发声的音高
  · 所有圆点被一条橙色曲线连起来，从第一个音符一直画到最后一个
  · 音符之间音高相差较大时，曲线在边界处平滑过渡，不会瞬间跳变
21.2 曲线怎么算出来的
  · 以音符的 key 为基准，再叠加该音符/该音轨上的 PIT（音高偏差）和 PBS（音高范围）
  · 音符开头如果有 POR（滑音时间），会画出一段从上一个音高滑过来的过渡
  · 为了让曲线看得清，自动颤音不画进曲线；颤音效果仍然照常参与合成
21.3 怎么用
  · 用它检查旋律是否有意外的音高跳变、滑音是否过长
  · 想改就点音符下方参数区的 PIT/PBS/POR，曲线会立即跟着更新
  · 非当前音轨用暗色曲线显示，切到哪条音轨哪条变亮

【22】播放指针中途停住（8.2.1）
22.1 原因
  · 边渲染边播放时，下一段音频的渲染时间偶尔会超过音频缓冲；系统把音轨移除后指针就停住，但界面还停在「停止」状态
  · 从中间继续播放、以及播放结束的判断也有错误，可能提前结束或误报「渲染中断」
22.2 现在的处理
  · 12 秒以上的工程先在后台完整渲染一遍再开始播放，状态栏显示渲染进度，完成后自动开始
  · 短工程仍然边渲边播，并先预缓冲一段；渲染失败或音频输出中断会立即停止并恢复「播放」按钮，不会卡在播放状态
  · 停止播放不会再误报「渲染中断，音频不完整」
22.3 使用建议
  · 长工程第一次播放前显示「正在渲染」是在准备音频，请稍等；之后再播会直接使用缓存
  · 如果仍然中断，把底部状态栏或错误提示的日志发出来

【23】XStudio 工程（.svip3，实验）
23.1 现在能读什么
  · 网易云音乐 XStudio 的 .svip3 工程可以直接「打开」，不需要先导出 MIDI
  · 读取歌声音轨和音符：位置、时长、音高、歌词、力度；工程速度与拍号
  · 音符位置在文件里是毫秒，导入时按工程速度换算成 BriVoice 的 tick
  · 只读工程结构，不读取、也不复制 XStudio 的音频或官方采样
23.2 限制
  · 目前不读 XStudio 的自动音高/参数曲线、音频轨和效果器，只保留音符
  · 如果工程结构遇到新版本字段，可能只导入部分音符；把 .svip3 发出来可以按实际结构补
  · 导入后仍需要选择自己的声库才能发声

【24】BriNeting 与神经声库（v9.2）
24.1 两种声库，两种引擎
  · 标准声库 .v4voice：默认走传统合成，按音高取该声库的实测谐波。也可以在神经模型界面手动开启 BriNeting 神经合成。
  · 神经声库 .v4neural：制作时选择「神经」，包内除实测谐波外还带 engine:"neural" 与 8 个声线参数；选中后固定由 BriNeting 基座驱动，不再走传统谐波查找。
  · 歌手选择列表里，凡是由 BriNeting 驱动的歌手，名字后面都有蓝色「AI」角标；传统合成的歌手没有。
  · 两个扩展名都从「声库 → 导入声库文件」或「从文件夹批量导入」进入，不要手动改扩展名。
24.2 制作 .v4neural
  · 工具 → 制作声库，类型选「神经 .v4neural」，再填声库文件夹和名称。
  · 生成在 /sdcard/BriVoice_root/voicebanks/；再到「声库 → 从文件夹批量导入」导入这个目录。
  · 第一次使用神经声库前，建议先训练一次 BriNeting 基座；没有基座时神经声库会退回基础合成。
24.3 训练 BriNeting 基座
  · 工具 → BriNeting 神经声学模型（v9.4）→「训练 BriNeting 基座」。读取本机所有声库的实测谐波，只学频谱规律，不读取音频采样，通常几秒完成。
  · 基座训练一次即可服务所有 .v4neural。也可以先选中某个传统声库，再点「微调当前歌手」，让它学习自己的细节；微调后的歌手同样显示 AI 角标。
  · 基座与微调模型保存在应用私有目录（_universal.v4neural 是基座，<声库 id>.v4neural 是歌手模型），下次启动自动恢复。
24.4 声线参数（8 个）
  · 神经模型界面 →「声线参数…」，可调：气息、张力、明亮、鼻音、吐字清晰度、颤音深度、DYN 响应、PIT/PBS 响应；0.5 为中性。
  · .v4neural 包里带一套默认值；你调过之后按歌手保存在本机，不改动包文件，重新导入同名声库仍可恢复默认。
  · 作用：气息影响气声和噪声；张力影响声门与 GEN；明亮影响高频倾斜；鼻音移动 F1/F2；吐字清晰度收窄辅音/共振峰带宽并提高辅音增益；颤音控制自动颤音深度；DYN 响应让力度曲线更陡；PIT/PBS 响应放大音高和滑音的手动调节。
24.5 神经引擎下的手动参数
  · DYN 的增益曲线更陡，动态参数越大越明显；PIT/PBS 的音分换算和 POR 滑音时间都受「PIT/PBS 响应」缩放；VIB 深度受「颤音深度」缩放。
  · BRE / CLE / GEN / POR 等原有参数仍然有效，并叠加声线参数，不是二选一。
24.6 能力与限制
  · 它替代的是“按音高找最近一条实测频谱”这一步；声门、共振峰、辅音和效果仍由原来的合成器负责。
  · 频谱包络模型，不是完整声学模型或声音克隆；全程不使用官方采样。
  · 手机上训练：基座通常几秒，微调再几秒；模型只有几十 KB 左右。
  · 限制：声库的元音和频段很少时提升有限；极端音高或很短的音素可能不如实测频谱稳定。
24.7 旧模型
  · 8.2.1 的单声库小模型和 v9.0/v9.1 的通用模型仍可读取；重新训练基座或微调后会自动升级为 v9 格式。

  · 只有指针接近视窗右边缘时才滚动跟随，不再每次回调都重算缩放；参数曲线区会跟着同一窗口移动，但不会改变缩放。

【26】指针连贯性（v9.2.3）
26.1 原因
  · 播放时音频层每 100 毫秒才上报一次播放位置，界面虽然能按帧刷新，但拿到的位置每 100 毫秒才变一次，所以指针看起来是一节一节跳。
26.2 修复
  · 播放位置改为约每 16 毫秒上报一次，界面每次收到位置就按下一帧刷新；界面仍然会合并回调，性能不足时只是少画几帧，不会积压。
  · 只改刷新频率，音频渲染、音色和导出结果都不变。
26.3 验证
  · 在 LDPlayer 上播放示例工程，3 秒内渲染 195 帧，约 65 fps，第 99 百分位帧耗时 16 ms；录屏逐帧检查时指针每帧移动 3-8 像素，不再整段停住。
  · 如果设备很慢，仍可在设置里关闭「播放时滚动跟随（同步）」，进一步减少绘制。
【27】播放位置采样线程（v9.2.3）
27.1 为什么还会一段段跳
  · v9.2.2 只是把上报间隔缩短到 16 毫秒，但上报仍由“写音频数据”的循环触发；短工程边渲染边播时，渲染器每 0.5-1 秒才交来一块数据，指针就只能跟着这些块跳。
  · 长工程是整段渲染完再播，所以只有最后一段看起来流畅。
27.2 修复
  · 播放开始后单独启动一个 16 毫秒的采样线程，持续读取 AudioTrack 已播放帧数并上报；写数据循环不再负责进度。
  · 前段边渲染边播时，指针也按声音实际播放连续移动；渲染卡住或音频输出中断仍会停止并恢复「播放」按钮。
27.3 验证
  · 在 LDPlayer 把示例工程速度调到 240 BPM（总长 4.0 秒，走边渲染边播），录屏逐帧检查：指针连续移动，相邻帧位移多为 10-20 像素，没有成片停住；最大位移约 40 像素，属于录屏掉帧。
  · 音频渲染、音色和导出结果都不变。
【28】指针与音频延迟校准（v9.3）
28.1 为什么指针会比声音早
  · 播放头读到的是“已经交给混音器”的帧，不是此刻喇叭正在响的帧；设备输出缓冲还会再加一段延迟。之前指针直接按播放头画，所以多数设备上会比声音早约 30–100 毫秒。
28.2 启动时自动测量
  · 打开软件约 1 秒后，后台会播放约 2 秒、几乎听不见的测试音，读取 AudioTrack 时间戳估算这台设备的真实输出延迟；结果保存在设置里，并用于播放开始时的指针补偿。
  · 播放过程中还会继续读当前音轨的实时时间戳，平滑跟踪输出延迟；换耳机、蓝牙或外放后不需要重开软件。
  · 测量只在本机进行，不录音、不上传。设置里可以关闭「启动时自动测量输出延迟」，也可以点「重新测量输出延迟…」随时再测。
28.3 手动微调
  · 自动测量后如果仍觉得指针偏早或偏晚，再用「指针延迟补偿」滑块微调：声音比画面慢时把指针往后拉（数值增大）。
  · 从旧版本升级后第一次自动测量会把旧的手动补偿归零一次，避免自动值 + 旧手动值重复补偿。
28.4 结果与限制
  · LDPlayer 上实测输出延迟约 31–33 毫秒，播放时指针会从位置里扣除这段时间，不再固定提前一帧左右。
  · 不同设备、耳机和蓝牙延迟不同，以自动测量结果为准；如果设备不提供时间戳，会弹出一次校准引导，按提示用手动滑块对齐。
【29】长工程指针漂移（v9.3.1）

29.1 现象
  · 长工程（例如 167 秒、824 个音符）播放时，指针会比听到的声音慢几拍；示例工程只有 7 秒，几乎看不出偏差。

29.2 原因
  · 指针补偿是两部分相加：启动时测得的输出延迟，加上旧版「指针延迟补偿」滑块的值。自动测量成功后旧滑块值如果还留着（最大 ±2500 毫秒，120 BPM 下正好约 5 拍），两者叠加就会把指针整体推到声音后面。
  · 播放中读取的实时时间戳，在部分设备上会把整段输出缓冲也算成延迟；长工程整段渲染完再播，缓冲瞬间被灌满，这个值更容易一路涨到上限。

29.3 修复
  · 自动测量成功后，手动滑块不再叠加，并自动归零；升级到 v9.3.1 后第一次启动会清理旧版留下的手动值。确实需要手动微调时，先取消「启动时自动测量输出延迟」的勾选，滑块才可用。
  · 实时时间戳只允许在测量值上下小幅修正（约 -80 到 +120 毫秒），不会再累积成大缓冲；只有自动测量不可用时才回退到手动补偿。
  · 总补偿上限从 900 毫秒收紧到 600 毫秒，避免任何单一来源把指针拉走。

29.4 验证与限制
  · LDPlayer 上播放 167 秒工程并连续采样 85 秒：播放头每 1000 毫秒增加约 44100 帧，与墙钟一致，输出延迟稳定在 29–34 毫秒，补偿没有随时间漂移。
  · 本次没有在真机上复现「慢 5 拍」；修复针对的是补偿叠加和时间戳漂移这两个可解释来源。若你的设备仍有偏差，可在设置里取消自动测量，再用手动滑块对齐。
【30】神经引擎 9.3.2（v9.3.2）

30.1 模型结构
  · BriNeting 从单隐层升级为两层 tanh 网络：基座 64/48，单歌手 64/48，声库模型 40/24。
  · 输入从 27 维扩到 33 维，新增开口度、前后舌位、F2-F1、F3-F2、清浊度、噪声重心等发音特征，让同一套网络能跨声库、跨音高泛化。
  · 输出仍是 64 个频带的对数包络（60 Hz–16 kHz），交给现有谐波合成器发声。

30.2 训练改进
  · 损失按频带加权：80 Hz–5 kHz 权重 1.6，5–10 kHz 1.15，10 kHz 以上 0.7，优先学清元音和共振峰。
  · 微调时加入 L2-SP 正则，把权重往 BriNeting 基座回拉，避免小样本把通用规律带偏。
  · 每 5 轮在留出的验证集上评估并保留最佳权重；35 轮没有改善就提前停止。

30.3 神经混合
  · 「声线参数」新增「神经混合」，默认 60%：六成神经包络 + 四成该歌手实测包络，保留个人共振峰；调到 100% 则完全使用神经包络。
  · 混合比例写在 .v4voice/.v4neural 里，换设备也会保留。

30.4 实测
  · 模拟器 21 个声库、5168 帧：验证损失 0.0845 → 0.0711（约 -16%）；干净安装 20 个声库、5260 帧：0.0759。
  · 单歌手微调（kawaiineko）：0.1959 → 0.1588（约 -19%）；洛天依 V4 中文·萌微调后 0.0570。
  · 旧版 v8.2.1/v9.1/v9.2 模型仍可读取；首次加载会自动扩成新输入维度，预测结果不变。

30.5 限制
  · 训练只读取 .v4voice 里已经测好的谐波频谱，不读取任何音频采样，也没有使用官方采样。
  · 它仍然只是频谱包络模型，不是 XStudio 级别的完整声学克隆；气声、辅音和效果器部分继续由现有引擎完成。
【31】多声库融合（v9.4）

31.1 做什么
  · 工具 → BriNeting 神经声学模型（v9.4）→「多声库融合（2 个以上声库）」；勾选 2 个以上已安装声库，起名或留空，点「开始融合」。
  · 融合模型把多个声库已测出的谐波规律放进同一个网络一起训练，得到一个介于这些歌手之间的新音色；参数量随声库数量上升（2 个声库约 1.66 万，单歌手微调约 8 千）。
  · 只读 .v4voice / .v4neural 里已测好的谐波，不读取音频采样；原声库版权归各自权利人。
31.2 使用
  · 训练完成会直接生成并安装一个「融合·…」声库，歌手列表里有「融」角标和 AI 角标；选中即可像普通神经声库一样合成、导出。
  · 融合声库固定使用 BriNeting 神经合成，不能退回传统谐波查找；想换回某个原始歌手，直接在歌手列表切换。
  · 每个声库只取一部分帧（总量有上限），声库越多、每个分到的越少；2–4 个声库效果最稳。
31.3 训练与容量
  · 模拟器上 2 个声库（洛天依 BV + Miku BV）实测：170 轮约 2–2.5 分钟，训练损失 0.0569 / 验证 0.0586；完成后 5038 帧、验证 0.0543、参数 16616。
  · 模型保存在应用私有目录；融合声库包写在声库目录，删除该声库时一起删除。
31.4 限制
  · 融合不是“混合两个声库的采样”，也不会生成新的发音习惯，只是把多个声库的频谱规律平均到一个网络里；音色差异大的声库融合后可能偏向其中一方。
  · 手机上训练仍是一次数分钟的离线计算，训练时可以继续操作界面，但不建议切走应用。

【32】本地调音模型 BriTune-Net（v10.0）

32.1 做什么
  · 工具 →「本地调音模型（BriTune-Net）」，或在 AI 快捷面板点「本地模型调音」；选风格（流行 / 抒情 / 摇滚 / 电子 / 国风），调「强度」和「应用幅度」，点「开始调音」。
  · 一个 68 → 192 → 96 → 11 的小网络（32,843 个参数，约 129 KB）在本机推理：输入是当前音轨的结构化工程数据（音符、歌词、间隔、跳动、速度、风格提示），输出 DYN / BRE / BRI / CLE / OPE / POR / VIB / PIT / GEN 曲线和力度微调，走的是和云端 AI 相同的 JSON 结构，因此可以撤销、可以「导出 JSON」。
  · 训练方式：用通用的中文虚拟歌手调音策略（长音渐弱、延迟颤音、句首气声、大跳滑音、高音减力、短音去颤，外加五种风格侧写）生成约 16.7 万个音符样本，再蒸馏进这个小网络；v2 的教师规则加入拍点（强拍 / 弱拍 / 反拍）、按音程与速度换算的滑音毫秒数，以及更细的风格侧写。
  · v2 修正了音高表情的单位：旧模型把「音分」直接当 14-bit PIT 值写入（1 音分 ≈ 0.024 unit），写进去几乎听不出来；现在按 PBS 换算（1 音分 ≈ 40.96 unit），滑音按真实毫秒换算，颤音按目标音分深度换算。
  · 全程离线：工程内容不会离开设备。

32.2 模型下载
  · APK 里不含权重。首次调音会在进度条里从 Gitee 仓库 aimodel/ 拉取模型文件（10.1.1 起是 britune-v3.bin，约 225 KB；旧版为 britune-v2.bin，约 129 KB），校验 SHA-256 后存到应用私有目录 files/model/britune-v1.bin（文件名沿用，内容按清单版本替换）；之后再调音直接用本地文件。
  · 「模型…」按钮可以看状态、手动下载 / 更新、删除模型；删除后下次调音会重新下载。
  · 清单文件 aimodel/local-model.json 记录版本、大小、SHA-256 和下载地址，所以模型可以单独升级，不必跟着 APK 发版。

32.3 进度与结果
  · 调音时进度条实时显示：下载模型 → 逐音符推理（每 16 个音符刷新）→ 生成 JSON。
  · 完成后状态栏给出「本地调音完成（风格）：N 处」，参数曲线出现在参数面板里；不满意的按两次撤销即可。
  · 和云端 AI 一样，它只会改已有音符，不会凭空加音符。

32.4 限制
  · 模型是规则蒸馏出来的小网络，不是大语言模型：它不懂自然语言要求，也不会读你的工程说明；要「按一句话调」仍用云端 AI 调音。
  · 参数偏移量以通用审美为准，强烈个人化的风格需要自己在曲线面板再改；「应用幅度」可以把整体改动收小到 10%。

【33】自学习与长工程时长（v10.0.1）

33.1 导出后自学习
  · 「导出WAV」成功后，弹窗里除了「分享 / 关闭」还有一个「满意，加入训练」：这次听着满意就点它，当前工程上的参数改动会变成一条条训练样本存进本机数据集（每条 = 一个音符的 68 维输入 + 11 维参数偏移）。
  · 点下去会立刻在本机重新训练：从当前权重出发，用 Adam 跑几十到两百轮，再按数据集规模把权重往原模型拉回一部分（样本少时只吸收一小步），所以一次「满意」不会把模型带偏，多满意几次它会越来越贴近你的口味。
  · 训练结果存成 files/model/britune-v1.user.bin，优先于发布版权重加载；工具 →「本地调音模型」→「模型管理」能看到「自学习：数据集 N 条 · 已用于当前模型」，也能「清空自学习数据」（回到发布版模型）或「用全部数据重训」。
  · 数据只在设备上：不上传音频、不上传工程、不上传样本。数据集上限 4000 条，超出后自动丢掉最旧的。
  · 工程参数全是默认值时点「满意」，会提示「本次没有可学习的改动」，不会写入空样本。

33.2 长音符 / 后面音符不唱（已修）
  · 现象：工程里片段不在 0 位置、或者工程很长时，播放和导出会提前结束，末尾的音符没唱，播放头也和卷帘错位。
  · 原因：渲染器按绝对时间写缓冲，但混音时又加了一次片段起点偏移，整段音频被推后「片段起点秒数」，末尾的音符越过缓冲尾部被丢掉。
  · 10.0.1 起合成、混音、片段预览、工程总长、WAV 导出统一用绝对 tick：末尾音符不再丢失，导出时长与工程长度一致。已被旧版本导短的工程重新导出一次即可。

【34】从音频分析表情与模型 v2（v10.1）

34.1 从音频分析表情（实验）
  · 入口：工具 →「从音频分析表情（WAV，实验）」，或工具菜单最下面一项；点「选择 WAV…」，选一段**干声独唱**（不要伴奏、不要和声）。
  · 做法：用 YIN 逐帧追音高、用 RMS 逐帧追响度，再按当前工程的音符时间表切片，把偏差写成 PIT（音准 / 滑音）、DYN（力度）、VIB（颤音）三条曲线；写入前会弹出报告：分析帧数、浊音比例、平均音准偏差、写入点数。
  · 只读本机、不联网；点「写入调音」后可以撤销（和 AI 调音一样进撤销栈）。
  · 前提：先载入与音频同节奏的工程（或先把音符对齐），否则音符窗口和唱句错位，报告里的平均偏差会虚高到几百音分；正确对齐时应在几十音分内。
  · 实测（5 音符测试工程 / 198 帧）：平均音准偏差 30 音分，写入 PIT 20 点 / DYN 15 点 / VIB 2 点，共 37 处；撤销后 PIT 回到 0 线，重做恢复。

34.2 BriTune-Net v2
  · 结构 68 → 192 → 96 → 11，32,843 个参数（约 129 KB），纯 Java 全连接推理，中端机每音轨几十毫秒级。
  · 训练数据：由拍点感知的中文调音规则生成 167,151 条音符样本（强拍 / 弱拍 / 反拍、滑音毫秒换算、长音延迟颤音、句首气声、句尾释放、大跳滑音、高音减力、短音去颤，外加流行 / 抒情 / 摇滚 / 电子 / 国风五种风格侧写），再蒸馏进小网络。
  · 验证集物理 MAE：力度 1.68 / 气声 0.42 / 明亮 0.32 / 清晰 0.54 / 开口 0.34 / 滑音 2.15（约 4 ms）/ 颤音 1.10（约 8 音分）/ 音高前段 54.99 unit（约 1.3 音分）/ 后段 28.51 unit。
  · 模型仍从 Gitee 的 aimodel/local-model.json 按版本下载，升级 10.1 后清单版本从 1 变 2，会拉取 britune-v2.bin 并校验 SHA-256。升级时会清掉基于旧基座的自学习权重（样本数据集保留，下次「满意，加入训练」会在 v2 上继续学），避免旧结构权重挡住新模型。

34.3 导入自己的模型
  · 工具 →「本地调音模型（BriTune-Net）」→「导入模型文件…」，选一个 .bin（BRTN 格式；68-192-96-11 的 v2 或 88-256-128-13 的 v3 都可以）。应用会先完整校验再替换，失败不会破坏当前可用模型；导入成功后版本标记为 imported，自动更新不再覆盖它；同时会删掉基于旧基座的自学习权重（样本数据集保留），确保导入的权重立即生效。
  · 删除模型或清空自学习后，重新调音会回到发布版 v2。

34.4 限制
  · 音频分析是单声部干声，不支持伴奏、合唱、说唱式快速咬字；气声、假声和强烈转音可能被判成静音或跑调。
  · YIN 的搜索范围 65–1000 Hz（C2–B5 附近），超出范围或大量噪声时请先降噪 / 升采样。
  · 这是「把唱腔表情搬进工程」，不是声音克隆，也不会改变声库本身的音色。


【35】BriTune-Net v3（v10.1.1）

35.1 改了什么
  · 结构 88 → 256 → 128 → 13，57,357 个参数（约 225 KB），纯 Java 在本机推理，不联网也能调音。
  · 每个音符的输入从 12 维扩到 16 维：新增小节内位置、强拍、反拍、与前一个音同音重复；5 个上下文槽 + 8 维全局共 88 维。
  · 输出从 11 维扩到 13 维：新增「音符内力度走向」（在音符末尾再写一个 DYN 控制点，让长音有自然的强弱起伏）和「延迟颤音起点」（VIB 先写 0，再在目标时刻升到深度，而不是一开口就颤）。
  · 验证集改为按歌切分（同一首歌的音符只会出现在训练或验证一侧），归一化只用训练集统计，指标不再被同歌样本泄漏抬高。

35.2 与同条件 v2 的对比（同一批未参与训练的歌、同一套规则标签、同样 44 轮）
  · 物理 MAE（越小越好）：力度 1.82 → 0.64；清晰 0.53 → 0.33；力度偏移（vel）0.70 → 0.34；新增的力度走向 0.26、延迟颤音起点 0.20（这两项是归一化单位）。
  · 变差一点的项：音高前段 56.3 → 68.8 unit（约 0.3 音分，听感上不可闻）；滑音 2.10 → 2.72 ms；气声 +0.11、明亮 +0.11、颤音深度 +0.10（约 0.03 个参数单位）。
  · 结论：v3 主要改善力度、咬字清晰度和力度曲线形状；音高绝对值精度略降但仍在 0.3 音分内，不能宣称所有维度全面超越 v2。

35.3 使用与升级
  · 入口不变：工具 →「本地调音模型（BriTune-Net）」，或参数面板的「AI 调音」里选本地模型。
  · 首次调音会按 aimodel/local-model.json 下载 britune-v3.bin（230,208 B，SHA-256 06468af0e9ce38e032e36dfe7ef7f00b0ffab876f95f2a0b645417e05f2956b2），旧 v2 权重被替换。
  · 升级到 v3 时会清掉基于旧结构的自学习权重（样本数据集保留，下次「满意，加入训练」会在 v3 上继续学），避免旧权重挡住新模型。
  · 想换回或用自己的模型：工具 →「本地调音模型」→「导入模型文件…」；加载器按文件头区分 68 维 / 88 维，v2 权重仍可正常加载（只是没有新增的力度走向和延迟颤音输出）。
  · 自学习数据集按模型代分开存放（v3 用 britune-self-v3.dat），旧的 v2 数据集不会被当成 88 维样本误读。

35.4 限制
  · 仍是规则蒸馏的小网络，不是端到端歌声合成，也不会理解自然语言要求；「按一句话调」请用云端 AI 调音。
  · 新增的两个输出只在 v3 权重下生效；v2 权重仍按旧行为只写单个 DYN / VIB 控制点。
  · 模型体积从约 129 KB 增到约 225 KB，首次启动下载时间会稍长；推理仍是逐音符全连接，中端机每轨几十毫秒。
