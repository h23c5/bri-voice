# VOCALOID4 声库的做法，与本项目采用的部分（实测）

参考对象：`E:\VoiceDB\LuoV4_Jpn\BTAMLDY8WSZS8TE8\Luotianyi_JPN_Normal.{ddb,ddi,vvd}`
（洛天依日文 Normal，2018 版；ddb 875,546,744 B / ddi 1,239,636 B / vvd 243 B）

## 一、三份文件各是什么（实测，不是推测）

| 文件 | 结论 | 依据 |
|---|---|---|
| `.vvd` | 243 B 的**文本**，每个字节 XOR 0x1A 后可读 | 解出 `"ID":=:"VOCALOID:VIRTUAL:VOICE" "FORMAT":=:"4.0.0.0" "VOICEIDSTR":=:"BTAMLDY8WSZS8TE8" "VOICENAME":=:"Luotianyi_JPN_Normal"` 以及 Breathiness/Brightness/Clearness/Opening/Gender:Factor/Growl 六个默认值 |
| `.ddi` | 索引：`DBSe` + `PHDC` 音素表 + 记录目录 | 0x9bd 起是一张音素分类表（Vowels / Nasals / VoicedPlosives / VoicedFricatives / VoicedAffricates / Liquids / Semivowels / UnvoicedPlosives / UnvoicedFricatives / UnvoicedAffricates / GlottalPlosive / Bresathings / Silence），随后是 `TMM `(`TDB `/`ARR `/`ARR `) 记录组，每带 pitch/dynamics/opening 三条 ARR |
| `.ddb` | 帧数据本体 | 全文 83,176 条 `FRM2` 记录，记录间隔几乎恒为 11,440 B（第 7 条起 11,448） |

**FRM2 一帧 = 32 B 头 + 2 × 350 × float32**：前半行是升序的谐波频率 k·f0（自动走到第一个不递增处，实测每帧 83~100 根），后半行 350 起是同一批谐波的 dB，未用槽位填 10000.0。
**帧率 256/44100 = 5.805 ms**；83,176 帧 ≈ 482.8 s ≈ 8 分钟纯语音。

所以 V 的做法一句话：**它不存波形，存的是每 5.8 ms 一张谐波谱**，音色来自这些实测谱，而不是共振峰模型。

## 二、它的"用好采样"是这四个手段（都已移植）

1. **按 f0 分音高档**：一个音素的帧按 f0 三分位切成低/中/高三带，每带至少若干帧才成立。
2. **按力度分档**：同一档内再按帧能量切软/中/响三份（`dyn = 0 / 0.5 / 1`），力度改变的是**音色**而不只是音量。
3. **存真实连续帧序列**：每格取 12 帧**连续**帧（int8，0.5 dB/步，base64 打包），播放时沿音符位置插值，谱才会随音符移动。手机 JSON 里逐个数会造出几十万个装箱 Double，所以必须打包。
4. **在线性幅度域平均**：多条谱取均值要先 `10^(dB/20)` 再平均、再转回 dB；直接平均 dB 会抹掉共振峰。

这四条在本项目旧版里**全都没有**：旧包每个音素只有 3 条"音高档"，而且三条曲线是**逐位相同**的同一份拷贝，没有任何序列。

## 三、照搬会踩的坑（本次实测修正）

- **f0 估计器偏一个八度**：旧 `f0_of` 取"归一化相关最大"的滞后，而 a_2.wav 实际 154 Hz（record.json 与波形一致），它算成 77 Hz。于是所有音高档都低一个八度，渲染时找不到靠近音符的档。改用 YIN（累积均值归一化差值 + 第一个过阈值的滞后 + 抛物线细化），并对每个 take 取参考音高、只保留 ±0.7~1.4 倍内的帧。
- **整场录音只有一个音高**：record.json 标 C4，实测中位数 201.7 Hz；500/700 Hz 的"音高档"是八度错误。加了整场窗口 143.2~286.4 Hz，丢掉 9.9% 的帧，零假档。
- **V 的门槛 40 帧/带**是为几万帧的声库定的；100 条短 take 只有 ~500 帧/元音，必须放到 12 帧/带，否则一条都存不下。
- **力度分档不能用归一化曲线的能量**：归一化后每条谱峰都是 0 dB，"能量"完全相同，排序等于没排。改用帧的真实 RMS；并且只保留中位数 −10 dB…+6 dB 内的帧（爆破段的强脉冲会把"响"档变成咔哒声，改前 soft/loud 相距 76 单位、改后同一族）。

## 五、仍有两处不如 V

- **只有单音高**：V 一条 take 里有 83 帧×很多音高，本项目 100 条短 take 全在 200 Hz 附近，高处只能靠同一条谱。要补就得按更高音再录一批。
- **序列只有 12 帧 ≈ 70 ms**：V 的整段音符是从长 take 里裁的，本项目 take 只有 0.5 s，能连成一条的连续帧有限（实测每条 4~12 帧）。

## 六、你说的"116 条"对不上

录音向导「全音素」档位显示 111 条（5 元音 + 19 辅音 × 5 元音里 G2P 能解析的 106 个），而 `build/banks/samples` 与包内 `record.json` 实际只有 **100 条**（19 个辅音 × 5 = 95 + 5 元音），少了 11 条未录。另有 161 条的是 UTAU 的 KawaiinekoCV，不是这一批。
