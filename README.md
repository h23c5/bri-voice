# BriVoice · Android 歌声合成 / 调音

以本机安装的 **VOCALOID4 Editor** 为蓝本实现的安卓歌声合成与调音软件。本体不内置任何音色，所有音色来自外部声库（.v4voice 标准声库 / .v4neural 神经声库）。

纯 Java 8 + 原生 Android 框架编写，不依赖 Gradle / AndroidX / 任何第三方库，直接调用 aapt2 / javac / d8 / zipalign / apksigner 打包成 APK。

---

## 〇、教程

**手机端制作声库**（最常问的）—— 应用内：工具菜单 →「教程」；仓库里：[docs/教程-声库制作.md](docs/教程-声库制作.md)

三语版本随应用内置：`app/assets/tutorial/voicebank.zh.txt` / `.en.txt` / `.ja.txt`（按当前界面语言自动选择）。

要点速览：

1. 声库是**文件夹**（含 `.ddb` / `.ddi` / `.vvd`），整个拷到手机，如 `/sdcard/VoiceDB/BK8H76TAEHXWSKDB/`
2. 工具菜单 →「制作声库」→ 选类型（标准 `.v4voice` / 神经 `.v4neural`）→ 填**文件夹路径** + 名称 → 开始转换（PC 约 20 秒，手机几分钟）
3. 产出位置在完成对话框里直接写明：一般是 `/sdcard/BriVoice_root/voicebanks/<id>.v4voice`（或 `.v4neural`）；没给「所有文件访问」（Android 10 或没打开该开关）时自动落到 `Android/data/com.bri.voice/files/BriVoice_root/voicebanks/`，两个目录「声库」页都会扫到
4. 包内只有**测量统计量**（谐波包络 / 共振峰 / 辅音噪声谱 / 帧序列），**不含任何原始录音**，全程离线
5. 测不到的就不写（不编造）：帧数不足 40 的音素不生成曲线；摩擦音素材少的声库只会命名 1~2 个辅音

## 一、功能

**编辑功能**
- 钢琴卷帘：128 键、可横向/纵向滚动、双指缩放、小节/拍网格、音名与歌词显示
- 音符编辑：新建、拖动改音高/位置、右边缘拖拽改时长、左边缘拖拽改力度、长按删除
- 歌词支持：拼音（luo）、汉字（内置 26709 字拼音表）、假名/罗马字
- 控制参数曲线：DYN、BRE、BRI、CLE、OPE、GEN、POR、PIT、PBS、VIB、XSY、GWL
- 试音：左侧琴键即发出该音高的 "a" 音
- 撤销/重做（24 步）、速度（BPM）、网格吸附
- 多轨工程：读取多轨 VSQX，逐轨渲染混音

**播放与输出**
- 播放：边渲染边播放，支持播放头拖动定位
- 导出 WAV：44.1 kHz / 16 bit / 立体声
- 打开 / 保存 / 另存为：支持 .vsqx / .vsq / .mid 格式

**神经与融合**
- BriNeting 神经引擎：两层网络、33 维发音特征、神经混合比例
- 多声库融合（v9.4）：选 2 个以上已装声库训练出新音色；只读已测谐波，不读音频采样

**声库管理（v12.1）**
- 「声库」按钮直接给出管理页：一行一个声库，带引擎角标、谐波统计与包体大小，当前歌姬高亮；点一行即切换
- 每行自带重命名 / 删除；重命名只改显示名（留空恢复原名），删除会连同该声库的神经权重一起移除
- 模型备份 `.bri`：把本机 BriTune-Net 权重与 BriNeting 基座打成一个文件（普通 zip，含 SHA-256 清单）；导入前完整校验，失败不动现有模型

**单模型导出与合并（v12.2）**
- 两个模型可分别导出：管理页的「导出 BriTune-Net」「导出 BriNeting 基座」各自写一个只含该模型的 `.bri`
- 导入时可选「替换」或「合并（各半）」：同结构权重平均后再走一次存盘 / 读回校验；结构不同会明确拒绝，不会悄悄退化成替换
- 采样录入新增「全音素」清单（111 条，5 元音 + 19 辅音 × 5 元音），清单条数与步骤提示、record.json 同源
- 自制声库可选「神经合成 / 采样合成」；两条路径都有 800 MB 上限，超限即报错并删除产物

**音高线（v12.3.1）**
- PIT 曲线区按**半音**画网格（每半音一条，八度更亮），左侧刻度与拖动气泡都用半音读（如 `PIT +1.5 st`），不用再自己把音分换算成半音
- 「选择」工具的**控制点可以左右拖**（改时间）也能上下拖（改音高），拖过相邻点自动重排；以前只能上下改，想挪位置得删了点重画
- PIT 工具条多一个**「吸附」**开关：开启后画笔 / 直线 / 拖点都落到最近的整半音；画颤音、滑音时关掉即可。只作用于 PIT，其它参数手感不变
- 桌面单元测试 `tools/pitch_selftest` 覆盖吸附取整与半音格式化（24 项）

**按屏幕分辨率分配编辑区（v26H1128V2）**
- 三条硬指标直接按窗口高度算：音符区 >= 1/2、调音区 >= 1/5、音轨条至少完整显示一条（标尺 16dp + 整行 38dp + 2dp = 56dp）
- 放不下时按优先级让：先让音轨条回到「一条」（多轨可滚动），再让调音区回到 1/5；此时日志打 layout v2: ... ROLL_FLOOR_HIT，缺多少可见，不再静默挤小
- 实测（480dpi、1920x1080、1 轨）：横屏窗口 1008px -> 卷帘 508px（50.4%）、调音区 202px（20.0%）、音轨条 168px（完整一条）；窗口铺满 1080px 时卷帘 566px（52.4%）；竖屏窗口 1848px -> 卷帘 1030px（55.7%）；280dpi 窗口 1038px -> 卷帘 653px（62.9%）
- 竖屏顶栏改成两行（原来一行约 480dp 塞不进 360dp 宽，最右边几个按钮被裁）：第一行新建/修改/选择/BPM，第二行吸附/拍号/混音/回起点/回终点/时钟；横屏仍是一行
- 横屏状态条压到 9sp 单行、音轨条标尺 18->16dp，省出来的都给了音符区

**按屏幕尺寸自适应布局（v26H1128V1.2）**
- 修掉「音符栏（钢琴卷帘）太小」：以前音轨条高度写死 18 + 38×轨数 dp（封顶 150dp），参数曲线区横屏固定 **138dp**、竖屏固定 **196dp**，钢琴卷帘只是「剩下的那一块」。手机横屏窗口本来就只有 300~360dp 高，扣掉顶栏和状态条后，卷帘常常只剩几十 dp
- 现在整列按**真实可用高度**分配：参数曲线区取 22%（64~160dp）、音轨条取 23%（38~150dp，且不超过它实际需要的行高）、钢琴卷帘拿走剩余；卷帘保底 55% / 140dp，不够时先从参数区扣（下限 64dp）、再从严从音轨条扣（下限 38dp）
- 高度只在真的变化时才写回，refreshTrackBar() 也不再反过来把音轨条钉死——以前它每次刷新都会把自适应算出来的高度覆盖掉
- 实测（同一台模拟器，1920×1080，2 轨工程）：480dpi 横屏（360dp 高）卷帘从 **220px 增至 444px**（约 2.0 倍）；5 轨工程旧版 450+414 > 808px 可用高度，卷帘被挤到 **0**，现在仍有 **444px**；280dpi（617dp 高）大屏上卷帘 419→507px（+21%），音轨条 262→212px、参数区 241→203px，没有把大屏做坏
**横屏左侧图标栏修复（v26H1128V1.1）**
- 修掉「手机横屏最左边显示不全」：左侧图标栏（新建 / 打开 / 保存 / 播放 / 撤销 / 重做 / AI 调音 / 更多）在横屏矮屏上排不下。旧算法把按钮步长锁死 **38dp** 下限、顶部 logo 区固定 **56dp**，8 个按钮合计 360dp 起步；而手机横屏的可用高度常常只有 300~360dp，最下面几项就被裁到屏幕外——实测 560dpi 横屏（1920×1080 → 308dp 高）时「重做」只剩半个、「更多」完全看不见
- 现在导轨按**实际高度**收缩：顶部 logo 区按高度 16% 自适应（30~56dp）、按钮步长按可用高度均分（下限 22dp）、按钮直径 / 图标 / 文字都跟着单元缩放，308dp 高的横屏也能把 8 项完整排下（480dpi、560dpi 横屏都验过）
- 同时补了**挖孔 / 刘海让位**：横屏时机身挖孔常常压在屏幕左边缘，如果系统把窗口铺到挖孔下面，图标栏会按挖孔安全边距整体右移；系统已经让开时算出来是 0，不会出现「系统让一次、代码再让一次」的双倍留白
- 边界：只处理左侧图标栏被裁与挖孔遮挡，钢琴卷帘的横向缩放/滚动逻辑没有改动

**工程保存修复（v26H1128V1）**
- 修掉「导入的工程退回开始界面，再从最近工程进去，工程在、参数和音节没了」：以前自动保存会**按文件扩展名挑写出器**，而 `.ust` / `.ustx` 两个写出器既没有参数曲线也没有音素——导入 `.ust` 之后第一次自动保存，源文件就被改写成只剩音符的 UTAU 文本（实测 615 KB / 6335 条曲线 / 834 条音素 → 25 KB / 0 / 0）
- 现在自动保存**只写原生格式**：导入非 `.vsqx` 的工程后，第一次自动保存会把当前内容转存成 `BriVoice_root/projects/<名字>.vsqx`，之后编辑、保存、重开都落在这份本地工程上；导入的那份源文件只读、不再被改写
- 最近工程列表跟着指向这份本地副本（同时把导入源那条去掉），所以从列表重开拿到的是带参数、带音节的那一份
- 顺手修掉文件名叠加与 SAF 串：以前每重开一次就多一层 `.vsqx`（`名字.vsqx.vsqx.vsqx`），列表里还会出现 `primary:BriVoice_root/projects/…` 这种文档 id。现在名字统一剥掉扩展名，只显示文件名
- 显式「另存为」成 `.ust` / `.ustx` 仍按你选的名字导出，但会同时留一份可编辑的 `.vsqx`，编辑器的保存目标不再指向没有曲线和音素的格式

**手动切换横竖屏（v26H1127V2.1）**
- 「更多」面板最后一行新增**手动切换横竖屏**：不管手机怎么拿着，点一下就在横屏 / 竖屏之间切换，不用转动机器
- 开始界面的「更多」页也有同一项，进工程之前就能选好方向
- 用的是「传感器版」方向（SENSOR_PORTRAIT / SENSOR_LANDSCAPE），锁定当前轴向的同时仍允许 180° 反向，横屏反着拿也能用；切换时沿用 v26H1127V2 的还原逻辑，卷帘缩放、位置、顶部音高和角色立绘都不丢

**竖屏适配（v26H1127V2）**
- 之前竖屏是坏的：右侧整列（音轨条 / 卷帘 / 参数区 / 状态栏）高度被算成 0，只剩左边图标栏，编辑区全黑。现在两种朝向用同一套骨架（图标栏 + 右侧竖排），竖屏下图标栏收窄到 56dp
- 竖屏细节：顶栏时钟缩小一号并留出下边距（不再被音轨条压掉第二行）；角色立绘在竖屏按**卷帘宽度**封顶（以前按高度缩放，竖屏会把立绘放大到盖住音符）；教程左侧章节栏在竖屏收窄到 190dp；「更多」面板竖屏用 88% 宽度，按钮不再挤成窄条
- **旋转不丢位置**：旋转后卷帘的缩放 / 横向位置 / 顶部音高整体还原，角色立绘也不会消失（以前换朝向后音符跑到视野外、立绘要重启才回来）
- 开始界面与教程这类整屏 Dialog 在旋转后会按新朝向重新排版，不会被裁掉半个屏幕

**声库导入修复（v26H1127V1）**
- 修掉「声库生成失败 · ENOENT / EPERM」：以前声库包硬写到公共存储根目录，Android 10 或没给「所有文件访问」的手机上 `mkdirs()` 静默失败，写到一半就报 `open failed`。现在先用**试写探针**确认目录真的能写，再决定落点（公共目录 / 应用自己的目录），完成对话框直接写出完整保存路径
- 同一个原因也修了「检查更新」的下载目录：以前 APK 同样写死到公共根目录，写入不了的机器上更新永远下载失败
- 失败对话框多一行「输出目录」，下次再出问题能直接看出是哪个目录被拒

**教程阅读器（v26H1127V1）**
- 教程改成整屏阅读器：左侧引导栏列出全部章节（当前章高亮、自动滚到当前章），点章节跳到该章首页
- 顶栏有「第 n / N 页」+ 上一页 / 下一页 + 页码输入框 + 跳转（全书 54 页）
- 左栏顶部是搜索框：输入关键词（如 WAV / PIT）列出「章节 · 页码 · 片段」，点一条跳到那一页并把匹配词高亮，顶部一行可退回章节列表
- 搜索是大小写不敏感的**子串**匹配，不分词、不支持拼音，最多列 60 条

**开始界面（v12.3）**
- 启动先进开始界面：**新建工程 / 打开工程 / 歌手管理器 / 更多** 四个入口，底下是**最近 5 个工程**（点一行直接打开，不经过文件选择器）
- 「更多」是二级页面：设置、教程、Gitee 项目主页、B 站主页（两者用系统浏览器打开）、关于
- 最近工程来自 `BriVoice_root/projects` 与打开过的文件，按时间倒序；文件被删或只有 0 字节（保存被打断）时不会出现在列表里
- 通过文件管理器「用 BriVoice 打开」进来时跳过开始界面，直接进编辑器；界面文案走 ZH/EN/JA 三语表

## 五、添加声库

应用支持导入外部 .v4voice / .v4neural 声库包；两种都通过「声库 → 导入声库文件」或「从文件夹批量导入」进入：

1. 在电脑上运行转换工具生成声库包：
   ```powershell
   python tools/voicebank_pack.py --bank "E:\你的声库目录" --out build/voicepacks/my_bank.v4voice
   ```

2. 把生成的 .v4voice / .v4neural 文件传进手机
3. 在应用内「声库 → 导入声库文件」选中该文件，或放进同一文件夹后「从文件夹批量导入」

## 六、代码结构

```
app/src/com/dsh/v4tune/
  model/     数据模型（Song、Track、Part、Note、Voice、ControlCurve）
  format/    格式读写（VsqxReader/VsqxWriter、Vsq2Reader/Vsq2Writer、MidiReader）
  phoneme/   音素处理（PhonemeDef、PhonemeTable、ChineseG2P、JapaneseG2P、PinyinDict）
  synth/     合成引擎（VoiceSource、FormantFilter、HarmonicVoice、FrameVoice、Renderer）
  audio/     音频引擎（AudioEngine、Mixer、PluginChain、DSP 插件）
  io/        文件操作（ProjectIO、PackStore、WavReader）
  ui/        界面（ PianoRollView、ParamView、Theme、Dialogs）
  ai/        AI 调参（AiTuner、ExtApi、Json）
  MainActivity.java
tools/      构建脚本与测试工具
```

**合成链路**：谱面 → 音素分段 → F0 曲线 → 声门源 → Klatt 共振峰 → 包络/动态 → 立体声混音
